# Product Principles

1. **Evidence before confidence.** Material claims must trace to evidence or be marked unknown.
2. **Decision support before chat.** The primary product is better program judgment, not conversational fluency.
3. **Official status and forecast status are different.** Human accountability and machine prediction must remain distinguishable.
4. **Surface contradiction.** Do not silently collapse conflicting evidence into invented ground truth.
5. **AI proposes; humans establish consequential ground truth.**
6. **The program manager remains accountable.** Program OS advises, monitors, forecasts, and recommends.
7. **Insufficient evidence is a valid result.** False certainty is a product failure.
8. **Historical performance modifies credibility, not truth.** Past misses can lower confidence without mechanically rewriting estimates.
9. **Optimize the portfolio, not one project in isolation.** Every intervention should expose collateral consequences.
10. **Deterministic logic handles deterministic facts.** Dates, hard gates, permissions, audit, and formal constraints should not depend on free-form model judgment.
11. **Overrides are evidence, not automatically truth.** Learn from the full sequence: recommendation, override, rationale, outcome.
12. **No silent self-modification.** Global AI behavior changes are proposed, evaluated, approved, versioned, monitored, and reversible.
13. **One agent before many agents.** Add orchestration complexity only when evals justify it.
14. **Program OS augments systems of record.** It is an intelligence and control layer, not another tracker.
15. **Measure before optimizing.** Architecture changes should be evaluated against fixed cases and explicit failure costs.
