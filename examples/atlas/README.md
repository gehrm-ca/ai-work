# Atlas Launch Program

Atlas is the fictional V2 evaluation portfolio for Program OS.

## Scenario

Atlas is an enterprise AI-enabled workflow product preparing for launch into a regulated customer segment.

The portfolio contains five interdependent workstreams:

1. Application & UX
2. Platform & Integrations
3. Data / AI
4. Security, Compliance & Testing
5. Commercial Launch & Operations

All Atlas data is synthetic.

## Planned evidence set

Target: approximately 40–50 artifacts.

Expected mix:

- 15–20 Jira-style issues and epics;
- 5 risk-register entries;
- 4–5 project/wiki pages;
- 4 meeting summaries;
- 3 testing or quality reports;
- 3 stakeholder decision records;
- 2 retrospective summaries;
- 2 budget snapshots;
- 2 launch-readiness/status reports;
- 2 resource/capacity snapshots;
- 1 portfolio dependency map;
- 1 milestone schedule.

Every artifact will have timestamps and source metadata so freshness can be evaluated.

## Planted scenarios

The V2 golden cases will include:

- a slipping integration dependency;
- a recovery plan that is more optimistic than comparable historical execution;
- an undocumented scope change;
- a shared-resource collision;
- a worsening defect trend;
- a required approval bottleneck;
- contradictory source evidence.

## Example contradiction

A deliberately inconsistent case may contain:

- Jira updated Nov. 12: integration due Nov. 18;
- project page updated Nov. 4: integration due Nov. 14;
- meeting summary Nov. 11: engineering expects Nov. 20;
- executive status Nov. 7: on track.

Correct Program OS behavior is not to invent a confirmed date.

It should expose the contradiction, evaluate freshness and authority, reduce confidence, assess critical-path impact, and create a follow-up to establish ground truth.

## Canonical demo outcome

The system should be able to demonstrate that official reporting is healthier than the operational evidence supports, then produce an evidence-backed forecast, intervention, human decision, audit record, and Friday status update.
